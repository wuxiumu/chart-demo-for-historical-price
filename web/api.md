# K线看板 API 接口文档（供 AI / 程序接入）

> 本文档描述本站（kline-board，K线看板）对外提供的全部行情查询接口，面向 AI 助手与程序化调用。
> 所有接口均为**本站自有服务**（`/api/*` 路径），返回 JSON（UTF-8），支持跨域（CORS `*`）。
> 数据为第三方公开行情的整理展示，仅供研究与可视化演示，不构成任何投资建议。

## 基本信息

- **Base URL：即本文档所在站点的根地址（同源）**。例如本文档位于 `https://example.com/api.md`，则接口就是 `https://example.com/api/kline`。本地调试时为 `http://localhost:8787`。
- 所有接口均为 **GET** 请求、**免鉴权**（无需 token / key）、返回 JSON（UTF-8）、**支持跨域（CORS `*`）**——AI / 任意网页脚本可直接抓取本文件后按文档调用。
- 统一响应结构：`{ "code": 200, "msg": "ok", "data": <业务数据> }`
  - `code === 200` 表示成功；`4xx` 为请求参数问题，`5xx` 为服务暂时不可用（`msg` 含原因）
- 市场代码 `market`：`17` = 沪市，`33` = 深市
- 股票代码 `code`：6 位数字，如 `600519`（贵州茅台，market=17）、`300502`（新易盛，market=33）
- 限频建议：单一接口不超过 1 次/秒；盘中数据约 5~15 秒更新一轮，非交易时段请求不会得到新数据
- A 股交易时段（Asia/Shanghai）：周一至周五 09:25–11:31、12:55–15:05（午休 11:30–13:00 无数据变化）

## 1. 服务健康检查

```
GET /api/health
```

响应示例：

```json
{ "code": 200, "msg": "ok", "hasToken": true, "ts": 1792983149108 }
```

| 字段 | 说明 |
|---|---|
| hasToken | 数据通道是否已配置（false 时 /api/stock-list 与 /api/kline 可能不可用） |
| ts | 服务器当前毫秒时间戳 |

## 2. 自选股实时快照

```
GET /api/stock-list
```

返回看板全部自选股的实时报价列表。**非交易时段可能返回空数组**，请自行处理。

`data` 为对象数组，主要字段：

| 字段 | 说明 |
|---|---|
| stockCode / stockName | 代码 / 名称 |
| market | `17` 沪 / `33` 深 |
| currentPrice | 现价 |
| changePrice / changePercent | 涨跌额 / 涨跌幅（%） |
| openPrice / highPrice / lowPrice / prevClose | 开 / 高 / 低 / 昨收 |
| fluctuationPercent | 振幅（%） |
| volume / turnover | 成交量 / 成交额 |
| turnoverRate | 换手率（%） |

## 3. K线数据（日K / 分时）

```
GET /api/kline?market=17&code=600519&type=DAILY&adj=1
```

| 参数 | 必填 | 说明 |
|---|---|---|
| market | 否（默认 17） | `17` 沪 / `33` 深 |
| code | 是 | 6 位代码 |
| type | 否（默认 DAILY） | `DAILY` 日K / `INTRADAY` 当日分时（1 分钟线） |
| adj | 否（默认 1） | `1` 前复权 / `0` 不复权（仅对 DAILY 生效） |

响应 `data[0]` 结构：

```json
{
  "code": "600519", "name": "贵州茅台", "market": "17",
  "klineData": [
    [20260105, 1325.4, 1341.98, 1324.79, 1337.02, 17400000, 23250000000, 2.02, 0.15, null],
    ...
  ]
}
```

**klineData 每根 K 线为长度 10 的数组**：

| 下标 | 含义 | 说明 |
|---|---|---|
| 0 | 日期 | DAILY：`YYYYMMDD` 数字；INTRADAY：Unix 秒时间戳（**仅最后一个动态点为毫秒**，>1e12 时请 ÷1000） |
| 1–3 | 开 / 高 / 低 | |
| 4 | 收（现价） | |
| 5 | 成交量 | **单位注意**：DAILY 历史完成 bar 为「股」，盘中最后一根动态 bar 可能为「手」；可用 `成交量×收盘价 ≈ 成交额` 是否成立来判定（约成立为「股」，差 100 倍为「手」）。INTRADAY 为该分钟量（股） |
| 6 | 成交额（元） | |
| 7–8 | 涨跌额 / 涨跌幅（%） | |
| 9 | 预留位（恒为 null） | |

- DAILY 数据自 2025 年初起，约 435 根
- INTRADAY 为当日已走完的分钟点，09:30 起；昨收请取**上一根不同日期** DAILY 的收盘价（上游在非交易日会把最后一根复制一份，直接取倒数第二根会得到假 0 涨跌）

## 4. 五档盘口

```
GET /api/quote5?market=17&code=600519
```

响应 `data.quote_data[0]` 含 `data_fields`（字段名数组）与 `value[0]`（数值数组），**必须按字段名对位取值**（顺序不保证）：

| 字段名 | 含义 |
|---|---|
| 24 / 26 / 28 / 150 / 154 | 买1–买5 价格 |
| 25 / 27 / 29 / 151 / 155 | 买1–买5 挂单量（**股**，÷100 = 手） |
| 30 / 32 / 34 / 152 / 156 | 卖1–卖5 价格 |
| 31 / 33 / 35 / 153 / 157 | 卖1–卖5 挂单量（股，÷100 = 手） |

即：买价 = 买量字段下标减一。读法示例（伪代码）：

```js
const f = {}; q.data_fields.forEach((n, i) => f[n] = i);
const row = q.value[0];
const buy1 = { price: row[f["24"]], vol: Math.ceil(row[f["25"]] / 100) }; // 手
```

## 5. 当日逐笔成交明细

```
GET /api/trace?market=17&code=600519
```

响应 `data.quote_data[0].value` 为最近 100 笔，每笔长度 5：

| 下标 | 含义 | 说明 |
|---|---|---|
| 0 | 成交时间 | Unix **毫秒**时间戳 |
| 1 | 成交价 | |
| 2 | 方向 | `1` 买盘（外盘）/ `2` 卖盘（内盘）/ `3` 中性 |
| 3 | 当日累计量 | 股（只增不减，可用于校验顺序） |
| 4 | 单笔成交量 | 股（≥100 时 ÷100 显示为「手」，零股不足 100 股原样显示） |

## 6. 股票搜索（全市场联想）

```
GET /api/search?q=茅台
```

按代码或名称/拼音联想，返回最多 10 条：`[{ "code": "600519", "name": "贵州茅台", "market": "17", "label": "SH" }]`。可用结果中的 `code + market` 直接调用 /api/kline、/api/quote5、/api/trace。

## 典型调用流程（供 AI 参考）

1. `GET /api/health` 确认服务可用
2. `GET /api/search?q=名称或代码` 定位股票，得到 `code` 与 `market`
3. `GET /api/kline?market=&code=&type=DAILY` 取日K → 最后有效一根的 `close` 即现价；与上一**不同日期**的 bar 收盘价相减得涨跌
4. 盘中可补充 `type=INTRADAY`（分时）、`/api/quote5`（五档）、`/api/trace`（逐笔），5 秒级轮询即可
5. 所有失败请读取响应的 `code` 与 `msg`，避免盲目重试（建议失败后至少等待一个刷新周期）
